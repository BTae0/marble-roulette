# 마블 룰렛 재구현 설계서

작성일: 2026-10-14 / 용도: 개인용 / 위치: `C:\AI\marble-roulette\`

## 1. 목표와 범위

- 목표: lazygyu 마블 룰렛과 같은 규칙(이름 입력, 구슬 물리 경주, First/Last/Multiple 당첨, 맵 선택)을 더 세련되고 현대적인 UI로 처음부터 재구현한다.
- 원본 코드는 복사하지 않는다. 규칙과 개념만 참고한다. 원본 라이선스는 미확인.
- 개인용이며 Artifact를 사용하지 않는다. 로컬 정적 웹 앱으로 만든다. GitHub 업로드는 요청 시에만 진행한다.
- 1차 범위: 핵심 룰 + 내장 맵 4종 + 결과 화면 + 현대적 UI.
- 범위 밖(2차): 스킬, 녹화, 맵 에디터, 맵 공유, 효과음.

## 2. 기술 스택

- Vite + TypeScript, planck.js(Box2D 계열 물리), Canvas 2D 렌더링
- 테스트: Vitest(단위/시뮬레이션), Playwright(브라우저 확인)
- 실행 환경: Node.js v24 / npm 11 (설치 확인 완료)

## 3. 구조

```
src/
  main.ts            앱 시작, 화면 전환
  game/
    engine.ts        planck.js 월드, 고정 타임스텝(1/60초) 시뮬레이션
    marble.ts        구슬 생성, 색상, 끼임 감지 및 탈출
    rules.ts         First / Last / Multiple 판정 (순수 함수)
    names.ts         입력 파싱, Shuffle (순수 함수)
    maps/            맵 정의(데이터) 4종
  render/
    renderer.ts      Canvas 렌더링, 카메라 추적, 트레일
  ui/
    setup.ts         설정 화면
    result.ts        결과 오버레이
  styles.css         디자인 토큰, 다크 테마
```

화면 흐름: 설정 → Start → 경주 → 결과 오버레이(다시 하기 / 설정으로).

## 4. 입력 파싱 (names.ts)

- 쉼표 또는 줄바꿈으로 구분. `이름*N`은 N개로 확장. 앞뒤 공백 제거, 빈 항목 무시.
- 같은 이름은 같은 색과 라벨로 표시하며 순위는 구슬 단위로 계산한다.
- `*0`, 음수, 숫자가 아닌 값은 해당 항목을 무시하고 경고를 표시한다.
- 최대 구슬 수 200개(초과분은 잘라내고 경고).
- Shuffle은 Fisher–Yates로 시작 순서만 섞는다.

## 5. 당첨 규칙 (rules.ts)

[2026-10-14 변경] 타임아웃을 없애고, 모드와 관계없이 **전체 구슬이 도착할 때까지** 경주를 진행한다. 결과 화면은 마지막 구슬 도착 후에 표시한다.

| 모드 | 판정 |
|---|---|
| First | 가장 먼저 도착한 구슬 |
| Last | 마지막으로 도착한 구슬 |
| Multiple | 도착 순서 상위 K명 |

- K는 설정 화면에서 숫자로 직접 입력한다. 범위는 1 ~ 구슬 수이며 범위 밖이면 자동 보정한다.
- 결과 화면에 전체 도착 순위를 보여준다.
- 타임아웃과 강제 유도(하향 힘, 충돌 해제)는 없다. 구슬이 끼면 끼임 탈출 임펄스가 연속 실패 횟수에 비례해 강해진다.

## 6. 물리 (engine.ts, marble.ts)

- 중력 4 m/s², 구슬 선형 감쇠 0.4(경주 시간 확보용), 고정 타임스텝 1/60초, 렌더링과 분리.
- 구슬은 원형 바디. 반발 계수와 마찰은 맵별 지정. 질량은 동일.
- 끼임 감지: (a) 2초 동안 이동 거리 5 mm 미만, 또는 (b) 15초 동안 최대 진행 깊이(y)가 갱신되지 않으면 임펄스로 탈출시킨다. 연속으로 끼일수록 임펄스를 키우되 상한(12배)을 둔다.
- 슬라이더 이동 범위의 양 끝은 벽에서 구슬 지름(0.44 m) 이상 떨어져야 한다(맵 검증 테스트로 고정).
- 초기 미세 오프셋만 시드 기반 난수(mulberry32)로 결정하여 같은 시드는 같은 결과를 재현한다(디버깅/테스트용).
- 결과의 공정성(균등 확률)은 보장되지 않는다. 맵 형태가 결과에 영향을 주며 UI에 작게 안내한다.

## 7. 맵 데이터 (maps/)

- 맵은 코드가 아닌 데이터(JSON 구조)로 정의한다. 2차 맵 에디터 대비 형식을 고정한다.
- 필드: 이름, 크기, 구슬 시작 구역, 결승선, 정적 도형(선분/박스/원 기둥), 움직이는 장애물(회전 막대/좌우 이동판).
- 내장 맵(높이 126~133 m의 다단계 코스, 구슬 10개 기준 45초 이상 소요, 막대·슬라이더 속도는 기본값의 1.7배): ① 핀볼 ② 지그재그 ③ 회전 풍차 ④ 깔때기. 맵 길이는 100~140 m로 제한한다(테스트로 고정).
- 변수 환경(zones): 맵마다 3개 이상, 2종 이상을 둔다.
  - wind: 구역 안 구슬에 가속도를 준다(ax, ay). period가 있으면 sin 파형으로 방향이 주기적으로 바뀌는 돌풍이 되고, ay만 있으면 가속 구역이다.
  - slow: 속도에 비례한 저항(damping)을 준다.
  - portal: 구슬을 도착점 목록 중 무작위(시드 난수)로 순간이동시킨다. 도착점은 항상 입구보다 위쪽이며, 재진입 쿨다운은 1.5초다.

## 8. UI

**설정 화면**
- 참가자 입력은 칩(태그) 방식이다(roster.ts). 이름을 입력하고 Enter 또는 쉼표(IME 조합 중에는 제외)로 추가하며, 쉼표·줄바꿈·탭으로 구분한 여러 명 붙여넣기와 `이름*N` 표기도 지원한다.
- 같은 이름은 한 칩으로 합쳐 개수를 늘린다. 칩마다 개수 −/＋ 버튼과 삭제(×)가 있고, 1 미만이 되면 삭제된다. 이름은 30자까지 사용한다.
- 보조 기능: 번호로 추가(5/10/20 → 1번~N번), 순서 섞기(칩 순서), 모두 지우기. 총 구슬 수는 200개로 제한하고 초과 시 경고한다.
- 저장값은 칩 목록(entries)이다. 이전 형식(text)은 읽어서 칩으로 이전하고, 손상된 값은 기본 목록으로 복구한다.
- 맵 선택: 미리보기 썸네일 카드 4개.
- 당첨 방식: 세그먼트 토글. Multiple 선택 시에만 K 입력칸 표시.
- Start 버튼 강조. 구슬이 1개 미만이면 비활성화.

**경주 화면**
- 전체 화면 캔버스. 카메라가 선두(Last 모드는 꼴찌)를 보간 추적한다. 줌인 연출은 1차 범위에서 제외. 마우스(터치) 드래그와 휠로 화면을 위아래로 옮길 수 있으며, 이때 자동 추적이 꺼지고 "자동 추적" 버튼으로 다시 켠다.
- 좌측 상단 실시간 리더보드(상위 5개), 우측 세로 미니맵.
- 속도 배율(1x/2x/4x), 일시정지, 처음으로 돌아가기.

**결과 오버레이**
- 당첨자 카드 강조, 색종이 효과, 전체 순위 스크롤 목록.
- 버튼: "같은 설정으로 다시"(새 시드), "설정으로 돌아가기", 결과 텍스트 복사.

**디자인**: 다크 기반 글래스 패널, 네온 포인트 컬러, 구슬 이름 라벨과 트레일. 모바일 세로 화면 대응.

**상태 저장**: 마지막 입력 이름/맵/모드를 localStorage에 저장하고 복원한다. 접근 불가 시에도 동작하도록 예외 처리한다.

**접근성/성능**: 라벨 대비 WCAG AA 목표. `prefers-reduced-motion`이면 색종이와 트레일 축소. 구슬 200개에서 60fps 목표이며, 구슬이 80개를 넘으면 트레일을 끈다.
